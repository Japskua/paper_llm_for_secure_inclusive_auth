# Human evaluation package

The six best-scoring generated applications — one per case, per user story —
packaged for human expert evaluation.

Two evaluations are run against these same six artifacts:

| Evaluation | What the expert receives | Instrument |
|---|---|---|
| **Security** | the source code, in `source_code/` | `survey_questionnaires/security_evaluation_survey.pdf` |
| **Inclusivity** | a live, clickable application | `survey_questionnaires/inclusivity_evaluation_survey.pdf` |

## What these six artifacts are

Each was generated by `openai/gpt-5.6-terra` from a requirements document. Within
a story, the functional goal and the security requirements are identical across
all three cases; **only the inclusivity specification changes.**

| Case | Inclusivity specification given to the model |
|------|---------------------------------------------|
| 1 | None. Functional goal and security requirements only. |
| 2 | The condition is named, nothing more. |
| 3 | The condition is described, with concrete inclusivity requirements. |

| Story | Application | Condition |
|-------|-------------|-----------|
| 1 | Password recovery for a health portal | ADHD |
| 2 | MFA enrolment for online banking | Dyslexia |

Each case produced **ten** independent runs. These six are the highest scoring
of their ten, as ranked by the LLM judge panel — they are the best the model
produced, not the typical output. `final_evaluations/results_v2/cross_study/`
holds all sixty.

## A — Source code for security evaluation

`source_code/` — six files, one per artifact, named for their story and case:

| File | Lines | LLM security score |
|------|-------|--------------------|
| `story1_password_recovery_ADHD__case1_no_spec.ts` | 805 | 3.978 |
| `story1_password_recovery_ADHD__case2_condition_named.ts` | 724 | 4.044 |
| `story1_password_recovery_ADHD__case3_detailed_guidance.ts` | 587 | 3.867 |
| `story2_mfa_enrolment_dyslexia__case1_no_spec.ts` | 625 | 4.622 |
| `story2_mfa_enrolment_dyslexia__case2_condition_named.ts` | 675 | 4.678 |
| `story2_mfa_enrolment_dyslexia__case3_detailed_guidance.ts` | 501 | 4.578 |

Every file is **byte-identical** to what the model produced. Nothing was
formatted, fixed, or annotated. `source_code/MANIFEST.csv` records each file's
SHA-256, verified against `generations/<story>/batch_manifest.json`, so a
reviewer can confirm they are reading unmodified model output.

Each is a single self-contained file: a Bun HTTP server, plus an HTML template
with inline CSS and vanilla JavaScript for the client. There are no imports
beyond `node:crypto` / `node:fs`, no dependencies, and no build step.

### Blinded set

`source_code_blinded/` holds the same six files as `artifact_A.ts` …
`artifact_F.ts`, with the mapping in `BLINDING_KEY.csv`.

Use this set if security experts are asked to score more than one artifact. The
descriptive file names state which experimental condition each file came from,
and an expert who can see that a file is "case 3, detailed inclusivity guidance"
may score it differently for that reason alone. The LLM panel had the same
exposure and it is already noted as a limitation; the human evaluation does not
have to inherit it. **Keep `BLINDING_KEY.csv` with the coordinator, not in the
material sent to experts.**

### Running an artifact locally

Reviewers who want to execute the code as well as read it:

```bash
curl -fsSL https://bun.sh/install | bash          # Bun 1.3.x

brew install mkcert && mkcert -install            # macOS; see mkcert docs for Linux
mkdir -p certs && mkcert -key-file certs/key.pem -cert-file certs/cert.pem \
  localhost 127.0.0.1 ::1

PORT=8443 bun story2_mfa_enrolment_dyslexia__case3_detailed_guidance.ts
# then open https://localhost:8443
```

All six require TLS certificates at `certs/cert.pem` and `certs/key.pem`
relative to the working directory — they exit rather than fall back to HTTP.
Each picks its own default port; set `PORT` to override. OTPs, reset codes and
backup codes are simulated and printed to the browser console, by design of the
original requirements.

## B — Live applications for inclusivity evaluation

*Hosting is being set up; this section will carry the six URLs, the demo
credentials, and the walkthrough instructions for experts.*

Note for whoever configures it: all six keep their state **in process memory**,
and several key it globally rather than per session. Two experts using the same
instance at the same time will interfere with each other — one can enrol MFA or
consume the backup codes for the other, and five failed sign-ins locks the
shared demo account for everyone for ten minutes. Each expert needs their own
instance, or a reset between sessions.

## Provenance

- Selection: highest combined LLM-panel score of the ten runs in each case, from
