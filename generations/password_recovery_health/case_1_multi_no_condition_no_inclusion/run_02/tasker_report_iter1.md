## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete HTML/CSS/vanilla-JS SPA, and exposes no external assets or network calls.
- Implement secure server defaults: redirect or reject non-HTTPS requests, set HSTS, CSP, frame, MIME-sniffing, referrer, and cache-control headers, and return generic production-safe errors without stack traces or directory listings.
- Implement session management with cryptographically random, Secure, HttpOnly, SameSite cookies and a unique CSRF token per session; require and validate the token for every state-changing endpoint.
- Implement a privacy-preserving recovery request screen that accepts an account email/identifier without revealing whether an account exists, validates input safely, and browser-console-logs a deterministic mock recovery delivery value for testing.
- Generate recovery tokens with cryptographically secure randomness, bind each token to its requesting session/account, enforce a short expiry and one-time use, and support both reset-link and manual-token submission paths.
- Implement recovery-token verification with generic failure feedback and server-side throttling/temporary blocking for repeated invalid attempts; ensure no token, user, or patient data can be accessed by changing client-supplied identifiers.
- Implement a password reset screen that validates the recovery token and enforces a strong password policy before accepting a new password; hash the password with Bun-supported bcrypt or Argon2 rather than storing plaintext.
- Add a deterministic mock MFA verification step after password reset, log the test code only in the browser console, accept the valid code without expiry, and throttle repeated failed MFA attempts.
- Implement an authenticated privacy-conditions acceptance flow required before appointment booking, enforcing session ownership and CSRF validation so another user cannot view or update its state.
- Implement a protected mock appointment-confirmation flow after privacy acceptance that uses only authenticated server-side state and never exposes patient identifiers or records in URLs, page content, or errors.
- Build all client views with semantic HTML and inline CSS/vanilla JavaScript, use safe DOM APIs or explicit escaping for every dynamic value, and ensure malicious input cannot create HTML, execute scripts, or control redirects.
- Ensure every internal navigation, recovery link, form submission, confirmation screen, and error path is handled by routes or client-side navigation in app.ts, with no broken anchors, dead paths, open redirects, or external URLs.
- Add clear app.ts comments mapping the session/CSRF/access-control, output-escaping, HTTPS/header/token, authentication/throttling/password/MFA, and anti-phishing protections to the numbered security requirements; include safe-authentication guidance that passwords and codes must never be shared via email or with support.
