## PARSED_TASKS
- Create a single runnable app.ts Bun server that serves the complete HTML/CSS/vanilla-JS SPA and uses certs/cert.pem and certs/key.pem for HTTPS; redirect HTTP requests to HTTPS without exposing errors or directory listings.
- Add security response headers for all routes, including HSTS, a restrictive CSP compatible with the embedded client script, X-Content-Type-Options, X-Frame-Options, Referrer-Policy, and a restrictive Permissions-Policy.
- Implement server-side in-memory session state with cryptographically random, Secure, HttpOnly, SameSite=Strict session cookies and a unique CSRF token per session.
- Implement CSRF validation for every state-changing endpoint, rejecting missing, invalid, or cross-session tokens without making any state change.
- Implement only allowlisted application routes and API endpoints, with authenticated sensitive endpoints checking the current session rather than accepting user or patient identifiers from the client.
- Create the password-recovery request screen with semantic HTML, accessible labels, safe-authentication guidance, and a generic response that does not disclose whether an account exists.
- Implement recovery-request handling with rate limiting and browser-console mock delivery of a cryptographically random reset token/link; keep the token server-side, bind it to its sessionless recovery record, and never include private account data in responses.
- Implement reset-token verification that accepts both the mock link token and manually entered token, enforces short expiry and single use, rate-limits failed guesses, and provides clear non-sensitive error feedback.
- Implement the password-reset form with a strong password policy, confirmation field, server-side validation, and password storage using Bun’s Argon2 or bcrypt password hashing rather than plaintext.
- Implement deterministic mock MFA after a valid reset token, log the mock code in the browser console, validate it with rate limiting, and allow the code to remain usable for the required simulated flow.
- After successful password reset and MFA, create an authenticated session and show a privacy-conditions acceptance screen; require an authenticated session plus valid CSRF token to record acceptance.
- Add a confirmation screen and working internal navigation for every recovery, manual-token, MFA, privacy-acceptance, and completion path without external links, fetches, redirects, or dead routes.
- Ensure client rendering never injects user-controlled values as HTML, validates inputs for usability only while the server remains authoritative, and prevents unsafe URL handling or open redirects.
- Add concise code comments in app.ts mapping the HTTPS, headers, CSRF/access control, XSS handling, token lifecycle, hashing/MFA/throttling, and anti-phishing measures to the numbered security requirements.
