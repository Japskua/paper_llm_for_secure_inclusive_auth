## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete SPA at approved routes, and redirects/rejects insecure HTTP requests without exposing debug details.
- Implement the complete semantic password-recovery UI as inline HTML, CSS, and vanilla browser JavaScript in app.ts, including account recovery request, reset-token verification (link and manual entry), MFA verification, password reset, privacy-statement acceptance, and confirmation screens.
- Implement in-memory, privacy-preserving recovery state so account-recovery responses never disclose whether an account exists or expose usernames, patient data, folders, or private identifiers.
- Generate cryptographically random reset tokens tied to the initiating session, expiry, and intended recovery record; make tokens single-use, accept manual token submission, and log the deterministic/mock delivery details only with console.log in the browser.
- Require a unique CSRF token per session and validate it for every state-changing recovery, verification, password-update, and privacy-acceptance request; reject missing, invalid, or cross-session tokens.
- Enforce authorization and ownership checks on every sensitive route/action so browser-supplied record IDs, token IDs, or redirect targets cannot access another recovery session or protected data.
- Add brute-force protections for reset-token, MFA, and password-related verification attempts, with scoped attempt limits/throttling and clear non-sensitive feedback when attempts are blocked.
- Implement a deterministic mock MFA step whose displayed/logged browser code always verifies, while binding successful MFA verification to the current recovery session and logging simulated delivery only in the browser console.
- Enforce a strong password policy and store only a secure bcrypt or Argon2 password hash in in-memory state; never render, log, or retain the submitted plaintext password after processing.
- Prevent XSS and injection by validating all request inputs, safely encoding all dynamic UI text, avoiding untrusted inline script/content execution, and ensuring user-controlled values cannot create redirects or markup.
- Configure HTTPS security headers including HSTS, a restrictive CSP compatible with the inline SPA, X-Content-Type-Options, clickjacking protection, referrer protection, and secure cookie attributes; ensure errors are generic and do not reveal stack traces.
- Validate every navigation/return URL against an internal allowlist, provide anti-phishing and safe-authentication guidance in the UI, and ensure no external network calls, remote assets, or support-impersonation flows exist.
- Add concise source comments in app.ts mapping each security control and recovery-flow behavior to the numbered requirements, and verify all internal links/forms complete their intended flow without dead paths.
