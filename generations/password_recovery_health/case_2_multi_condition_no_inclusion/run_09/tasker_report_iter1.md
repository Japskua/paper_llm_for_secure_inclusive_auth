## PARSED_TASKS
- Create a single runnable app.ts Bun HTTPS server that loads certs/cert.pem and certs/key.pem, serves the complete inline HTML/CSS/vanilla-JS SPA, redirects HTTP to HTTPS, and returns secure headers including HSTS and a restrictive CSP.
- Implement server-side in-memory sessions with cryptographically random, HttpOnly, Secure, SameSite cookies and unique CSRF tokens; require and validate the session CSRF token on every state-changing endpoint.
- Implement a privacy-preserving password-recovery request screen that accepts an account email without revealing whether it exists, rate-limits requests, creates a cryptographically random short-lived single-use reset token for the mock account, and returns the deterministic test token only for browser console.log.
- Implement reset-token verification through both a reset-link route/query value and a manual token-entry form; validate expiry, single use, session/flow binding, throttled failed attempts, and show clear generic feedback without exposing patient or account identifiers.
- Implement a password-reset form that enforces a strong password policy, validates CSRF and the verified reset flow server-side, hashes the replacement password with Bun-supported bcrypt or Argon2 rather than storing plaintext, invalidates the token, and logs only simulated delivery/update events in the browser console.
- Implement a mock MFA verification step after password reset with a deterministic code displayed only via browser console.log, throttled verification attempts, CSRF protection, and a successful authenticated session only after valid MFA.
- Implement authenticated privacy-statement acceptance and appointment-confirmation screens; enforce server-side authentication and authorization for their APIs, avoid user-controlled object IDs, and store only minimal in-memory mock state.
- Make all client rendering safe by using static markup and DOM textContent/validated values rather than interpolating user input into HTML, avoid external resources and remote fetches, and ensure every navigation/link/form route in the recovery flow works.
- Add concise code comments in app.ts mapping HTTPS/headers, CSRF/access control, XSS-safe rendering, token/password/MFA controls, rate limiting, and anti-phishing/open-redirect safeguards to the numbered security requirements.
