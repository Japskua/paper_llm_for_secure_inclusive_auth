## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete application from /, and rejects or redirects non-HTTPS requests safely.
- Add restrictive security headers on every response: CSP without inline event handlers or third-party sources, HSTS, X-Content-Type-Options, frame protection, referrer policy, and a restrictive permissions policy.
- Embed a semantic password-recovery SPA in the server HTML response using only inline CSS and vanilla browser JavaScript, with no external assets, frameworks, build steps, or network calls.
- Implement client-side route/state rendering for recovery request, token verification, password creation, MFA verification, privacy acceptance, and completion screens so every internal navigation path works without dead links.
- Implement an in-memory session model with opaque random session IDs in Secure, HttpOnly, SameSite=Strict cookies and a unique CSRF token per session.
- Require and validate the session CSRF token for every state-changing endpoint, rejecting missing, invalid, or cross-session tokens without changing state.
- Create a password-reset request endpoint that accepts a non-identifying account contact value, always returns a generic confirmation response, and logs a deterministic test reset token to the browser console without exposing patient identifiers.
- Generate reset tokens with cryptographically secure randomness, bind each token to its requesting session and recovery record, enforce a short expiry and single use, and reject invalid, expired, reused, or session-mismatched tokens.
- Allow the recovery token to be submitted manually in the verification UI and, after successful verification, move only that session into the password-reset stage.
- Enforce throttling for recovery-token verification, MFA verification, and password-related authentication actions, with clear generic feedback and no information disclosure.
- Enforce a strong password policy on the server and store the replacement password only as a Bun-supported bcrypt or Argon2 hash; never return, log, or retain plaintext passwords.
- Implement a deterministic mock MFA challenge after password reset, log its test code only in the browser console, and require successful MFA before access to privacy acceptance.
- Protect privacy-statement acceptance behind the authenticated recovery session, record acceptance only for that session, and prevent query parameters or client-supplied identifiers from selecting another user or record.
- Escape all server-rendered dynamic values and render client-provided text with safe DOM APIs such as textContent, never innerHTML, to prevent script execution and untrusted redirects.
- Provide visible anti-phishing and safe-authentication guidance stating that passwords and codes must not be shared by email or callers, and ensure all post-action destinations are fixed internal routes.
- Add concise comments throughout app.ts mapping the CSRF/access-control, XSS/injection, HTTPS/token, authentication/MFA/password, and SSRF/social-engineering measures to the numbered requirements.
