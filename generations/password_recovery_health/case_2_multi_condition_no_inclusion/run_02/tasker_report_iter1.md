## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete SPA from one route, and returns generic production-safe errors without stack traces or directory listings.
- Add security headers to every response: HSTS, a restrictive CSP compatible with the embedded application, frame protection, MIME sniffing protection, referrer policy, and cache prevention for recovery/authentication responses.
- Implement an in-memory session model with cryptographically random, HttpOnly, Secure, SameSite cookie values and a unique CSRF token bound to each session.
- Implement server-side CSRF validation for every state-changing request, rejecting missing, invalid, or session-mismatched tokens without changing state.
- Create semantic, accessible password-recovery UI views in the inline HTML for requesting recovery, entering a received token manually, setting a new password, MFA verification, privacy acceptance, and confirmation; ensure all navigation works in the single-page flow.
- Implement a generic password-recovery request endpoint that does not reveal whether an account exists and logs deterministic mock delivery details, including the returned test token, in the browser console only.
- Generate recovery tokens using cryptographically secure randomness, store only a cryptographic hash with session/account binding, expiry, and used status, and enforce single-use short-lived token validation.
- Add reset-token verification by both in-app link/query handling and manual token submission, with clear but non-sensitive feedback for expired, invalid, reused, or valid tokens.
- Enforce rate limits and temporary lockouts for recovery-token, MFA, and password-reset verification failures, returning safe retry feedback without exposing account identifiers.
- Enforce a strong password policy server-side and store the replacement password only as a bcrypt or Argon2 hash; never expose or retain plaintext passwords after processing.
- Implement deterministic mock MFA that must be completed after a valid reset token and before changing the password, logs its test code in the browser console, and accepts the provided code reliably.
- Require a completed authenticated recovery/MFA session before allowing privacy-condition acceptance, protect this sensitive action with CSRF validation, and prevent access to protected flow state through guessed identifiers.
- Ensure every user-controlled value is validated and escaped before display, avoid unsafe DOM sinks such as innerHTML for untrusted input, and prevent arbitrary redirect targets by allowing only predefined internal flow routes.
- Add visible safe-authentication guidance warning users not to share passwords or codes by email or with callers, and make clear that the portal does not request credentials through external links.
- Add concise source comments in app.ts mapping the server, client, and security controls to the relevant numbered security requirements and single-file/no-network constraints.
- Verify all application interactions are local mocks with browser console.log delivery simulation, no external network calls, no local imports, no framework, and no files other than app.ts required to run with bun app.ts.
