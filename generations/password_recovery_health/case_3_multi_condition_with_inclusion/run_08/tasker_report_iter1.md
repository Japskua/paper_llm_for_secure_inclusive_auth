## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete application, and requires no build step or local dependencies.
- Implement a plain HTML/CSS/vanilla-JavaScript recovery UI inline in app.ts with semantic structure, an accessible low-distraction layout, and no external assets, frameworks, or network calls.
- Implement persistent step-by-step recovery progress in the browser so a user can pause, reload, and resume without losing the current recovery step or entered non-sensitive recovery details.
- Provide clear, consistent screens for account identification, reset-code/link verification, new-password creation, sign-in, privacy-condition acceptance, and appointment-booking confirmation, with working internal navigation for each flow.
- Add visible next-step guidance, clear success and error feedback, accessible help access on every screen, and no countdowns, session-expiry messaging, or unexpected navigation.
- Implement a password-reset request endpoint that accepts only validated account identifiers, responds without revealing whether an account exists, and generates a cryptographically random reset token with a short expiry and single-use status.
- Return the mock reset token to the browser only for the evaluation flow and log its simulated delivery with console.log in the browser; support both reset-link and manual-code submission.
- Implement secure reset-token validation that rejects expired, used, malformed, or incorrect tokens and gives the user clear non-sensitive recovery guidance.
- Implement new-password validation with a documented strong password policy, confirmation matching, and clear inline feedback; store resulting passwords only as bcrypt or Argon2 hashes.
- Implement sign-in with hashed-password verification, generic failure messages, per-account/IP attempt throttling or temporary lockout after repeated failures, and a working MFA step using a deterministic mock code that does not expire.
- Protect authenticated actions, privacy-condition acceptance, and appointment confirmation with server-side session authorization so no user or patient record can be selected through client-controlled identifiers.
- Issue secure session cookies and unique per-session CSRF tokens, and validate CSRF tokens on every state-changing request including reset requests, password updates, login/MFA completion, privacy acceptance, and appointment confirmation.
- Prevent injection by validating all request data, escaping any user-controlled value rendered into HTML, avoiding unsafe DOM insertion, and rejecting untrusted script or redirect inputs.
- Configure HTTPS-only security headers including HSTS, a restrictive CSP, clickjacking protection, MIME sniffing protection, referrer protection, and a restrictive permissions policy; return generic production-safe errors without stack traces or directory listings.
- Ensure every redirect or continuation target is a fixed internal route or allowlisted value, and display safe-authentication guidance that passwords and verification codes must never be shared with email or support staff.
- Add concise code comments in app.ts mapping each security control and major UI behavior to the relevant numbered requirement sections.
