## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete responsive SPA as inline HTML/CSS/vanilla JavaScript, and uses no external assets, network calls, build steps, or local modules.
- Implement authenticated in-memory server sessions with cryptographically random opaque HttpOnly/Secure/SameSite cookies, session rotation at authentication, idle and absolute expiry, logout invalidation, and generic unauthenticated/expired-session responses.
- Add server-side authorization middleware to every MFA route that derives the account solely from the session and rejects supplied, manipulated, or guessed account identifiers.
- Implement CSRF tokens bound to the authenticated session and require validation for every MFA state-changing request, including authenticator enrolment verification, MFA enablement, recovery-code regeneration, and logout.
- Configure HTTPS-only handling and security headers on all responses: CSP, HSTS, X-Content-Type-Options nosniff, clickjacking protection via frame-ancestors and/or X-Frame-Options, and a trusted-origin-only CORS policy.
- Implement a mobile-legible semantic enrolment flow covering sign-in/identity verification, authenticator provisioning, OTP confirmation, successful MFA activation, recovery-code display, recovery-code regeneration, and logout; ensure every internal navigation action resolves through an implemented route or SPA view.
- Generate authenticator secrets, verification challenges, and recovery codes with cryptographically secure randomness; store OTP secrets encrypted or strongly protected in memory and store recovery codes only as strong hashes.
- Provide simulated authenticator provisioning with a manual secret-entry option and return deterministic testable provisioning/verification values to the browser UI; log these mock delivery/provisioning values only with browser console.log, never server logs or URLs.
- Implement server-side OTP and recovery-code verification that is single-use where applicable, time-bound, rate-limited, and locks the MFA verification flow after repeated failures while allowing valid non-expiring academic test codes where required.
- Validate all request inputs server-side (including email, phone, OTP, CSRF token, and recovery code), reject malformed input generically, and enforce an allow-list for any redirect destination.
- Render all dynamic UI values using contextual escaping or safe DOM text APIs, avoid browser storage for secrets/session data, and ensure secrets, OTPs, recovery codes, and session tokens are absent from URLs, server logs, and error responses.
- Add concise code comments in app.ts mapping the authentication, authorization, CSRF, headers, cryptography, validation, session, rate-limit, and client-rendering logic to the numbered security requirements.
