## PARSED_TASKS
- Create a single runnable app.ts Bun application that serves the complete responsive mobile SPA as inline semantic HTML, CSS, and vanilla JavaScript, with no external assets, frameworks, build steps, or local modules.
- Configure the Bun server to use certs/cert.pem and certs/key.pem for HTTPS, reject insecure requests as appropriate, and return generic production-safe errors without stack traces.
- Apply security headers on every response: a restrictive CSP, HSTS, X-Content-Type-Options: nosniff, and clickjacking protection through frame-ancestors and/or X-Frame-Options; restrict CORS to the trusted local origin only.
- Implement authenticated server-side sessions using Secure, HttpOnly, SameSite cookies, session rotation at authentication, idle and absolute expiry, and session invalidation at logout.
- Authorize every MFA route on the server using only the authenticated session identity, never a client-supplied user identifier, and reject unauthorized or manipulated requests consistently.
- Issue and validate an anti-CSRF token for every state-changing MFA request, including authenticator activation, OTP verification, backup-code use, and backup-code regeneration.
- Build the mobile-friendly sign-in and identity-verification flow with generic responses that do not reveal account existence; simulate delivery only through browser console.log and deterministic test values returned to the UI.
- Generate verification codes with cryptographically secure randomness, enforce single use and expiration, and implement per-session/account failure limits and temporary lockout for repeated invalid attempts.
- Implement authenticator enrolment that creates a cryptographically secure shared secret, stores it protected at rest, presents provisioning details, and permits manual secret/code entry without placing secrets in URLs or browser storage.
- Implement server-side time-based OTP verification for authenticator activation and subsequent MFA checks, ensuring accepted OTPs are time-bound, single-use where applicable, and never logged by the server.
- Generate cryptographically secure backup recovery codes, store only protected representations at rest, display newly generated codes once in the UI with browser-console mock logging, and invalidate each code after successful use.
- Provide authenticated MFA settings actions, including viewing safe enrolment status, enabling MFA, using a recovery code, regenerating backup codes, and logout; ensure each internal navigation path and form is handled within app.ts.
- Validate all server inputs by expected type and format (including email, phone, OTP, recovery code, CSRF token, and redirect target), allow redirects only to defined internal paths, and safely encode all dynamic HTML/DOM output.
- Ensure neither client nor server logs or persists OTP seeds, OTP values, recovery codes, or session tokens except that required mock OTP/recovery values are exposed only through the browser UI/browser console for evaluation.
- Add concise code comments in app.ts mapping each authentication, authorization, cryptography, validation, header, and UI control to the corresponding numbered security requirement.
