## PARSED_TASKS
- Create a single runnable app.ts Bun HTTPS server that loads certs/cert.pem and certs/key.pem, serves the complete inline HTML/CSS/vanilla-JS mobile SPA, and contains no local modules, build steps, external assets, or network calls.
- Add TLS-only security handling: reject or redirect non-HTTPS requests as appropriate, set HSTS, CSP, X-Content-Type-Options: nosniff, and clickjacking protections, restrict CORS to the trusted localhost origin, and return generic production-safe errors.
- Implement an in-memory authenticated-user session model with cryptographically random HttpOnly/Secure/SameSite cookies, session rotation at authentication, idle and absolute expiry, and logout invalidation.
- Implement server-side authorization middleware for every MFA read or mutation endpoint so the authenticated session identity, rather than any client-supplied user identifier, exclusively determines the accessible MFA record.
- Issue and validate per-session anti-CSRF tokens for every state-changing MFA request, rejecting missing, invalid, or cross-session tokens.
- Implement server-side validation for all submitted email, phone, OTP, recovery-code, and redirect inputs; allow redirects only to defined internal routes and ensure dynamic page/API output is contextually escaped.
- Implement cryptographically secure MFA enrolment data generation, storing OTP secrets and recovery codes only as encrypted or strongly hashed in-memory values and never persisting secrets, OTPs, recovery codes, or session tokens in browser storage.
- Implement deterministic mock authenticator provisioning with a manually submittable secret/code path, a time-bound single-use OTP verification path, and browser-console simulation output required for evaluator testing without placing secrets or tokens in URLs or server logs.
- Implement cryptographically secure backup-code generation, display each newly generated set only during its authorized enrolment or regeneration response, store only protected values, and invalidate prior codes whenever regeneration succeeds.
- Add server-side attempt tracking, rate limits, and temporary lockout for failed OTP and recovery-code verification attempts; return non-enumerating authentication failure messages.
- Build the responsive semantic mobile enrolment UI covering sign-in/identity verification, authenticator setup, OTP entry, backup-code storage guidance, MFA confirmation, MFA settings, backup-code regeneration, and logout.
- Wire the inline client JavaScript to the server routes using same-origin requests and CSRF tokens, render only server-authorized state, handle success and generic errors safely, and ensure every internal navigation/control reaches a functioning SPA route or endpoint.
- Add concise source comments in app.ts mapping each security control and flow to the applicable numbered requirement sections.
