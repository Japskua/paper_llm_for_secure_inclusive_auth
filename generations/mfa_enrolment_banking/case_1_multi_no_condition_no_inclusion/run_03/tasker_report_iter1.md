## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete responsive mobile SPA, and contains no local imports, build steps, external assets, or network calls.
- Implement authenticated in-memory session handling with opaque HttpOnly, Secure, SameSite cookies; rotate session IDs on authentication, enforce idle and absolute expiry on every MFA route, and invalidate the session on logout.
- Implement server-side MFA routes that derive the account solely from the authenticated session, reject missing/invalid sessions and any client-supplied or manipulated user ID, and restrict redirects to an internal allow-list.
- Add CSRF token generation and server-side validation for every state-changing MFA request, including authenticator enrollment confirmation, verification, backup-code regeneration, and logout.
- Implement cryptographically secure authenticator-secret and backup-code generation; retain only protected-at-rest MFA material (encrypted secret and hashes of recovery codes) in server memory and never expose stored secrets, OTPs, backup codes, or sessions through URLs, errors, or server logs.
- Implement deterministic, time-bound, single-use mocked authenticator verification and recovery-code verification, returning test-only provisioning/recovery values only in API responses needed by the UI and logging those values exclusively with browser console.log.
- Add per-session verification failure rate limiting and temporary lockout, with generic failure responses that do not reveal account existence or sensitive verification details.
- Validate all request inputs server-side (including email, phone, OTP, recovery code, CSRF token, and redirect target), reject malformed JSON/content types, and contextually escape all dynamic values rendered into HTML or client DOM.
- Serve the SPA with semantic mobile-friendly HTML, inline CSS, and vanilla browser JavaScript implementing sign-in, identity-verification simulation, authenticator provisioning with manual secret/code entry, MFA confirmation, recovery-code display/download acknowledgement, regeneration, and logout flows.
- Add security headers to every response: restrictive CSP suitable for the inline SPA, HSTS, X-Content-Type-Options: nosniff, clickjacking protection via frame-ancestors and/or X-Frame-Options, and a CORS policy limited to the trusted localhost origin; return generic non-verbose error responses.
- Add clear code comments in app.ts mapping the relevant server and client implementation sections to Security Evaluation Requirements 1 through 5 and the single-file/mobile/no-external-call delivery constraints.
- Verify every UI navigation, form submission, and API route works within app.ts without broken paths, browser storage, non-HttpOnly session storage, external requests, or sensitive browser/server logging beyond the explicitly required browser-console test mocks.
