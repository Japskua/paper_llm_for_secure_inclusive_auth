## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete responsive mobile SPA, and contains no local modules, build steps, external assets, frameworks, or network calls.
- Implement server-side session authentication state with opaque HttpOnly, Secure, SameSite cookies; rotate the session on authentication, enforce idle and absolute expiry, and invalidate it on logout.
- Add server-side authorization middleware for every MFA route that derives the account exclusively from the authenticated session and rejects missing, expired, manipulated, or guessed account identifiers.
- Set CSP, HSTS, X-Content-Type-Options, and anti-clickjacking headers on HTML and API responses; restrict CORS to the trusted localhost origin and return generic non-verbose errors.
- Implement CSRF token issuance and server-side validation for every state-changing MFA request, including enrolment verification, MFA enablement, backup-code use, and backup-code regeneration.
- Build a semantic, mobile-legible HTML/CSS/vanilla-JS SPA embedded in the server response, with working internal navigation for sign-in, identity verification, authenticator setup, confirmation, recovery-code management, and logout.
- Implement simulated sign-in and identity-verification flows with generic responses that do not enumerate accounts; generate deterministic testable verification values, return them only to the browser flow, and log them with browser console.log.
- Implement authenticated TOTP authenticator provisioning using a cryptographically generated secret, provide both a provisioning representation and manual secret entry, and require a valid submitted authenticator code before enabling MFA.
- Implement time-bound, single-use OTP verification with cryptographically sufficient code generation, server-side attempt tracking, rate limiting, and temporary lockout after repeated failures.
- Generate recovery codes using a cryptographically secure RNG, present them only after successful MFA enrolment through the UI and browser console, and support authenticated single-use recovery-code verification plus regeneration.
- Protect OTP secrets and recovery codes at rest using strong encryption or one-way hashing as appropriate, and ensure plaintext secrets, OTPs, recovery codes, and session tokens are never included in server logs, URLs, error responses, browser storage, or non-HttpOnly cookies.
- Validate all server inputs for expected formats and lengths (including email, phone, OTP, recovery code, CSRF token, and redirect target), escape all dynamic HTML output, and allow redirects only to defined internal paths.
- Add concise source comments mapping server and client security controls to the applicable numbered security requirements, including access control, headers, cryptography, validation, and authentication protections.
