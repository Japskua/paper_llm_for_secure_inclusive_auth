## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete responsive SPA, and has no local modules, build steps, external assets, or network calls.
- Implement authenticated server-side session handling with opaque HttpOnly, Secure, SameSite cookies, session rotation at login, idle and absolute expiry, logout invalidation, and generic authentication failure responses.
- Enforce authorization on every MFA route by deriving the account solely from the validated session and rejecting any supplied, manipulated, or guessed account identifier.
- Add CSRF protection to every state-changing MFA request and validate it server-side before changing enrolment, verification, recovery-code, or logout state.
- Implement the MFA enrolment API flow: authenticated identity confirmation, cryptographically generated TOTP secret provisioning, OTP verification, MFA activation, recovery-code generation, viewing, and regeneration.
- Ensure OTP verification uses deterministic testable mock behavior while enforcing single use, expiry, secure generation where applicable, failed-attempt rate limits, and temporary lockout; return test OTP/provisioning values only in API responses consumed by the browser.
- Generate recovery codes with a cryptographically secure RNG, store only strong hashes or encrypted values server-side, mark redeemed codes unusable, and never log or expose secrets, codes, or session tokens except the explicit browser test-display responses.
- Build a mobile-legible semantic HTML/CSS/vanilla-JavaScript SPA inline in app.ts, with working internal navigation for each enrolment, authenticator verification, recovery-code, confirmation, and logout screen.
- Implement client interactions using same-origin requests only; display simulated delivery/provisioning and recovery values through browser console.log without using browser storage or placing secrets in URLs.
- Validate all server inputs for expected type, length, and format (including email, phone, OTP, CSRF, and recovery codes), safely encode all dynamic HTML/DOM output, and restrict redirects to an internal allow-list.
- Apply HTTPS-only handling and security configuration: CSP, HSTS, nosniff, clickjacking protection, trusted-origin-only CORS, and generic production error responses with no debug traces.
- Add clear source comments mapping server and client controls to each applicable Security Evaluation Requirement section, and verify every route and form is handled within app.ts.
