## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete HTML/CSS/vanilla-JS mobile SPA inline, and has no local modules, build steps, frameworks, or external network calls.
- Add global production-safe server behavior: HTTPS enforcement, trusted-origin-only CORS, CSP with frame-ancestors 'none', HSTS, X-Content-Type-Options: nosniff, clickjacking protection, and generic non-verbose error responses.
- Implement authenticated server-side session state with opaque HttpOnly/Secure/SameSite cookies, session rotation at authentication, idle and absolute expiration, logout invalidation, and authorization checks on every MFA route that derive the account solely from the session.
- Implement CSRF token issuance and validation for every state-changing MFA request, rejecting absent or invalid tokens without changing in-memory state.
- Create server routes for sign-in/identity verification, authenticator enrolment/provisioning, OTP confirmation, recovery-code display, recovery-code regeneration, MFA settings retrieval, and logout; ensure every internal client link or form maps to a working route or SPA view.
- Implement cryptographically secure server-side generation of authenticator secrets, verification challenges, and recovery codes; retain OTP secrets encrypted/hashed and recovery codes hashed in memory rather than returning stored plaintext.
- Implement deterministic mock OTP verification that is time-bound and single-use, supports manual authenticator-secret/code entry, and never places OTPs, seeds, recovery codes, or session identifiers in URLs, server logs, error responses, or browser storage.
- Add per-session verification attempt limits and lockout behavior for failed identity, authenticator OTP, and recovery-code verification attempts, with generic responses that avoid account enumeration.
- Validate all request inputs server-side (including email, phone, OTP, recovery code, CSRF token, and redirect target), allow only internal redirect paths, and contextually escape all dynamic values rendered into HTML or DOM updates.
- Build the responsive, semantic mobile enrolment UI for Marcus’s complete flow: sign-in, identity verification, authenticator setup with manual entry, OTP confirmation, one-time recovery-code presentation, MFA settings, regeneration, and logout.
- Make all simulated delivery/provisioning values returned only through protected responses needed by the active UI and log the test OTP, authenticator secret/provisioning value, and recovery codes with console.log in the browser only.
- Add concise code comments in app.ts that explicitly map each server and client security control to Requirements 1–5 and identify the one-file, inline-client, mocked-flow constraints.
