## PARSED_TASKS
- Create a single directly runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete HTML/CSS/vanilla-JS mobile SPA, and has no local modules, build step, framework, external assets, or external network calls.
- Implement HTTPS-only request handling with a generic production-safe error response, trusted-origin-only CORS, CSP with frame-ancestors, HSTS, X-Content-Type-Options: nosniff, and clickjacking protection headers on all HTML/API responses.
- Implement secure in-memory account/session state with cryptographically random session IDs, server-side authenticated-owner checks on every MFA route, session rotation at sign-in, idle and absolute session expiry, and logout invalidation.
- Set session cookies only with HttpOnly, Secure, and SameSite attributes, and ensure client code does not store secrets, OTPs, recovery codes, or session tokens in browser storage or client-readable cookies.
- Implement CSRF token creation and server-side validation for every state-changing request, including identity verification, authenticator activation, backup-code regeneration, recovery-code use, and logout.
- Implement the sign-in and identity-verification flow with generic non-enumerating outcomes, server-side validation of submitted values, secure session establishment, and browser console.log simulation messages that do not reveal sensitive values.
- Build a responsive, semantic mobile enrolment UI with a dyslexia-friendly system typeface, generous spacing, readable sizing, icon-plus-text step cues, no animation or flashing content, and a consistently prominent current step and single primary action.
- Write short plain-language instructions and examples for each form input, provide easy-to-find help/retry controls at every flow step, and show plain success or error text that identifies the problem and the corrective action without blame.
- Implement deterministic mock identity verification code delivery: return the test code only in the authorized UI response, display it only through browser console.log, never place it in URLs or server logs, and permit retry/re-request without a reading time limit.
- Generate an authenticator secret with cryptographically secure randomness, retain it encrypted or strongly protected server-side at rest, and provide an authorized provisioning screen with QR and manual-secret options plus copy-to-clipboard support.
- Implement browser-side QR rendering without external libraries or network requests, and ensure manual authenticator-secret submission is supported when a QR code cannot be used.
- Implement deterministic mock authenticator OTP verification with a browser-console test value, single-use and time-bound server-side verification records, input validation, rate limiting, and temporary lockout after repeated failures.
- After authenticator verification, generate cryptographically secure backup recovery codes, store only strong hashes server-side, display the plaintext codes only once to the authenticated owner, and emit the test codes exclusively through browser console.log rather than server logs.
- Provide recovery-code copy and download/print-safe actions without browser persistence, require a plain confirmation before completing enrolment, and provide an authenticated CSRF-protected backup-code regeneration flow that invalidates prior codes.
- Implement authenticated MFA settings, recovery-code verification, and logout routes so each operation derives the account exclusively from the server-side session and rejects missing, expired, cross-account, guessed, or manipulated identifiers.
- Validate all server inputs (including email, phone, OTP, recovery code, CSRF value, and redirect target), use allow-listed internal redirects only, and contextually escape all rendered or client-inserted text to prevent reflected, stored, and DOM XSS.
- Ensure every mocked delivery/provisioning/verification event is logged with console.log in the browser while server logging and responses never expose OTP seeds, OTPs, backup codes, session IDs, CSRF tokens, or stack traces.
- Add concise source comments mapping the HTTPS/server setup, authorization, CSRF, session handling, cryptographic storage, validation/output encoding, verification controls, and accessible UI decisions to the corresponding numbered security and inclusivity requirements.
- Manually verify with bun app.ts that every visible internal navigation, form submission, retry path, copy action, provisioning option, recovery-code path, settings action, and logout flow works entirely within the single-file application.
