## PARSED_TASKS
- Replace the OTP generator and verifier with RFC 6238 TOTP: HMAC-SHA-1, an 8-byte big-endian counter, dynamic truncation, six digits, and the same period and algorithm declared in the otpauth provisioning URI. Verify that the server-generated test code matches a standards-compatible TOTP calculation.
- Replace publicly pre-filled Marcus credentials with a server-controlled simulated proof-of-identity flow that does not expose usable account credentials to unauthenticated visitors. Issue an owner session only after successful proof and keep the authenticated account identity derived solely from that session.
- Add server-side failed-sign-in attempt tracking keyed by appropriate account and client/session context. Temporarily lock further identity verification after repeated failures and return a plain-language message stating when and how to retry.
- Return deterministic test OTP and recovery-code values to the authenticated UI at the relevant enrolment steps and log those values with browser console.log by default. Ensure the documented deterministic values successfully pass the same server verification flow without exposing them in server logs, URLs, or browser storage.
- Add a reveal/hide control for the authenticator manual secret that displays it in a legible grouped format, while retaining copy-to-clipboard support. Keep the secret out of URLs, persistent browser storage, and normal server logs.
- Generate recovery codes exclusively on the server with cryptographically secure randomness after recent authenticator confirmation. Return each generated set only once to the authenticated UI, store only hashes server-side, and remove any endpoint behavior that accepts client-supplied recovery-code sets.
