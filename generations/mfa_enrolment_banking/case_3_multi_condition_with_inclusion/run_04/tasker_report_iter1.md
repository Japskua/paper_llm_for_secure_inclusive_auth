## PARSED_TASKS
- Create a single runnable app.ts Bun TLS server that serves the complete responsive SPA, reads certs/cert.pem and certs/key.pem, and uses no external assets, network calls, build steps, or local modules.
- Implement secure in-memory authenticated session handling with rotated HttpOnly/Secure/SameSite cookies, idle and absolute expiry, logout invalidation, and server-side ownership checks on every MFA API route.
- Add security middleware and generic failure handling: HTTPS enforcement, CSP with frame-ancestors, HSTS, nosniff, clickjacking protection, trusted-origin-only CORS, anti-CSRF validation for every state-changing request, and no secret/token logging or URL exposure.
- Implement the enrolment flow UI in inline semantic HTML, CSS, and vanilla JavaScript: sign-in/identity confirmation, authenticator setup, OTP verification, recovery-code display, and completion, with all internal navigation working without dead links.
- Design the mobile UI for dyslexia accessibility: legible typography and spacing, short plain-language instructions with examples and icons, stable uncluttered screens, prominent single primary actions, persistent help/retry options, explicit confirmation, and specific corrective errors without reading time limits.
- Implement simulated authenticator provisioning with a cryptographically generated secret stored protected at rest; provide a QR/provisioning option plus manual-secret reveal and copy controls, and log test-only provisioning details only in the browser console.
- Implement deterministic testable OTP verification that is server-validated, single-use and time-bound, rate-limited with temporary lockout after repeated failures, accepts manual entry/autofill, and returns neutral authentication errors.
- Generate cryptographically secure backup recovery codes, store only protected representations, display and copy them only during the permitted recovery-code screen, log test-only codes only in the browser console, and support protected regeneration after MFA verification.
- Validate all request inputs server-side (including email, phone, OTP, recovery code, and redirect targets), escape all dynamic browser output contextually, use only internal allow-listed redirects, and avoid browser secret persistence.
- Add concise comments throughout app.ts that map the implementation to the stated accessibility and Security Evaluation Requirements, including authorization, configuration, cryptography, validation, and authentication controls.
