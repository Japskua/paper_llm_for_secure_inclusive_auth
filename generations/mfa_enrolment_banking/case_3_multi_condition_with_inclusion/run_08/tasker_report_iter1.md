## PARSED_TASKS
- Create a single runnable app.ts Bun HTTPS server that serves the complete responsive SPA from inline HTML, CSS, and vanilla JavaScript, uses certs/cert.pem and certs/key.pem, and has no external dependencies, assets, network calls, or build step.
- Implement authenticated in-memory session handling with opaque HttpOnly/Secure/SameSite cookies, session rotation at sign-in, idle and absolute expiry, logout invalidation, and server-side ownership checks on every MFA API endpoint.
- Implement MFA enrolment API routes that enforce CSRF validation for every state-changing request, reject user-ID parameters that do not match the authenticated session, and restrict redirects/routes to defined internal destinations.
- Implement cryptographically secure server-side generation and protected in-memory storage for authenticator secrets, OTP challenges, and recovery codes; never place seeds, OTPs, recovery codes, or session tokens in URLs, server logs, error responses, browser storage, or browser-visible cookie values.
- Implement deterministic simulated authenticator verification and recovery-code verification with single-use, time-bound codes, failed-attempt rate limiting and lockout, while returning test-only mock values to the UI solely for browser console.log output.
- Build the mobile-first enrolment flow with semantic screens for sign-in, identity/code verification, authenticator setup, authenticator confirmation, recovery-code saving, and completion; ensure each screen has one prominent primary action and functioning back/retry/help/reveal/hide/re-request controls.
- Make authenticator setup minimise transcription by providing a QR-style provisioning option, a manually usable secret/code alternative, copy-to-clipboard controls, and browser console logging of test mock provisioning and verification values.
- Make recovery-code handling show generated codes only when needed, provide copy and print/download-safe options without browser persistence, require a clear saved-code acknowledgement before completion, and support secure recovery-code regeneration through the protected API.
- Apply dyslexia-inclusive mobile UI styling and wording: legible type and spacing, plain short instructions, input examples, icons paired with text, generous static layout, no movement or reading timer, clear progress/current-step cues, and specific non-blaming errors with fixes.
- Add validation and contextual output encoding for all client and server inputs, use generic production-safe errors, configure trusted-origin-only CORS, and set CSP, HSTS, X-Content-Type-Options, and anti-clickjacking response headers.
- Add clear app.ts comments that map each security control and accessibility behaviour to the corresponding numbered security and inclusivity requirements, and verify every internal UI action resolves to an implemented route or in-page screen.
