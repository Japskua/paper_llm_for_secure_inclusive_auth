## PARSED_TASKS
- Create a single runnable app.ts Bun HTTPS server that serves the complete responsive SPA from inline HTML, CSS, and vanilla JavaScript, using certs/cert.pem and certs/key.pem and no external assets, calls, build steps, or local modules.
- Implement an accessible mobile MFA enrolment flow with consistent step indicators, plain short instructions, icons, visible help, examples, generous spacing, dyslexia-friendly typography, no timers/animation, and one prominent primary action per screen.
- Implement mock sign-in and identity verification with secure server-managed sessions, session rotation after authentication, HttpOnly/Secure/SameSite cookies, idle and absolute session expiry, logout invalidation, and non-enumerating authentication errors.
- Implement server-side authorization for every MFA route so the authenticated session account alone can read or change its MFA state; reject supplied, manipulated, or guessed account identifiers.
- Add anti-CSRF token issuance and validation for every state-changing MFA request, with browser requests sending the token without storing secrets, OTPs, or session tokens in browser storage.
- Implement secure simulated authenticator enrolment: generate a cryptographically random secret, retain it only in protected server state using encryption or strong protected representation, show a provisioning/QR option plus a manually usable value, offer copy support, and log the test provisioning value only in the browser console.
- Implement deterministic, time-bound, single-use authenticator verification with validated OTP input, retry support, clear actionable errors, failed-attempt rate limiting/lockout, and server-side MFA activation only after successful verification.
- Implement cryptographically generated backup recovery codes stored as strong hashes, display them only after successful enrolment with copy/download-style assistance and browser-console test logging, and support protected regeneration that invalidates prior codes.
- Implement recovery-code verification with single-use consumption, expiry/attempt controls where applicable, clear retry errors, and no secret or code values in server logs, URLs, error responses, or persistent browser storage.
- Apply secure server configuration: HTTPS enforcement, CSP with restrictive sources and frame ancestors, HSTS, X-Content-Type-Options nosniff, clickjacking protection, trusted-origin-only CORS, generic production errors without stack traces, and internal redirect allow-listing.
- Validate all server inputs (including identity fields and OTP/recovery-code entries), safely encode all dynamic UI content to prevent reflected/stored/DOM XSS, and avoid unsafe HTML insertion.
- Add concise code comments in app.ts explicitly mapping each security control and accessibility feature to the corresponding numbered security and inclusivity requirements.
