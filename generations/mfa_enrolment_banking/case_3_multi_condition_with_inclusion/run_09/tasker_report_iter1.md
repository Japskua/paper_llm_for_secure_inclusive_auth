## PARSED_TASKS
- Create a single runnable app.ts Bun HTTPS server that serves the complete responsive HTML, CSS, and vanilla-JavaScript mobile MFA application, using certs/cert.pem and certs/key.pem when available and no external assets, network calls, build steps, or local modules.
- Implement authenticated in-memory session handling with opaque HttpOnly, Secure, SameSite cookies, session rotation after sign-in, idle and absolute expiry, logout invalidation, and server-side ownership checks on every MFA route.
- Add security middleware for HTTPS-only handling, restrictive trusted-origin CORS, CSP with frame-ancestors protection, HSTS, X-Content-Type-Options, and X-Frame-Options; return generic errors without debug details.
- Implement anti-CSRF token issuance and validation for every state-changing MFA request, rejecting missing or invalid tokens before any account state change.
- Build the plain-language, mobile-responsive sign-in and identity-verification steps with semantic HTML, dyslexia-friendly typography, generous spacing, icons, short examples, visible current-step status, help hints, and one prominent primary action per screen.
- Implement secure simulated verification-code generation and server-side validation with cryptographic randomness, single-use and time-bound behavior, retry/re-request support, failed-attempt rate limiting/lockout, and non-enumerating error messages.
- Implement authenticator enrolment with a cryptographically generated secret stored protected at rest, a provisioning/QR option, accessible manual-secret entry, copy-to-clipboard support, and deterministic mock OTP verification that can be completed without a reading deadline.
- Implement backup recovery-code generation using cryptographic randomness and protected-at-rest storage; provide accessible copy and download/display options, one-time recovery-code verification, and CSRF-protected regeneration.
- Ensure simulated OTP delivery, provisioning details, and recovery-code test values are exposed only through the browser UI/browser console as required for testing, while server logs, URLs, errors, cookies, and browser storage never contain OTP seeds, OTPs, recovery codes, or session tokens.
- Validate all request inputs server-side (including email, phone, OTPs, recovery codes, and redirects), allow redirects only to internal allow-listed paths, and contextually encode all dynamic UI content to prevent injection and XSS.
- Implement the complete predictable enrolment flow—sign-in, identity check, authenticator setup, authenticator confirmation, backup-code storage confirmation, success, retry, help, and logout—so every internal navigation path works within app.ts and each action plainly confirms the result and next step.
- Add concise code comments in app.ts mapping the implemented server and client controls to the stated MFA, accessibility, and security requirement sections.
