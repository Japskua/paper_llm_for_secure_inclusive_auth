## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete responsive SPA HTML from that file, and has no local modules, build steps, frameworks, external assets, or network calls.
- Add production-safe server defaults: HTTPS-only handling, CSP with restrictive frame-ancestors, HSTS, X-Content-Type-Options: nosniff, clickjacking protection, trusted-origin-only CORS, and generic error responses without stack traces.
- Implement an in-memory authenticated-session model with cryptographically random HttpOnly, Secure, SameSite cookies; rotate the session on sign-in, enforce idle and absolute expiration on every protected request, and invalidate it on logout.
- Implement server-side ownership checks for every MFA route so the authenticated session determines the account and any supplied or guessed account/user identifier is rejected without revealing other account data.
- Implement cryptographically secure MFA secret and recovery-code generation, encrypt or strongly hash stored MFA material in memory, and ensure secrets, OTPs, recovery codes, and session tokens are never placed in URLs, server logs, errors, browser storage, or non-HttpOnly cookies.
- Implement CSRF protection for every state-changing MFA request, validate the token server-side against the authenticated session, and reject missing or invalid tokens with a safe error response.
- Implement strict server-side validation for all submitted fields (including email, phone, OTP, recovery code, and redirect target), allow redirects only to known internal paths, and contextually escape all dynamic values rendered into HTML or returned to the client.
- Implement simulated OTP enrolment and verification endpoints with deterministic test values delivered only to the browser response and browser console.log; make codes single-use, time-bound without imposing a reading deadline in the UI, sufficiently random where generated, and never log them on the server.
- Add per-session verification-attempt rate limiting and temporary lockout for repeated failures, with non-enumerating responses and explicit, user-friendly client guidance for retrying after a failed code entry.
- Implement protected backup-code generation, display, copy, download/print-friendly handling, confirmation, and regeneration; mark each recovery code single-use and return deterministic mock codes to the browser console for evaluation.
- Build the inline vanilla-JS SPA flow for sign-in, identity verification, authenticator setup, OTP verification, recovery-code storage, completion, MFA settings, and logout; ensure all buttons, forms, retry/reveal/hide/re-request actions, and internal navigation resolve to working routes or client state.
- Make the mobile UI semantic and dyslexia-inclusive: use a legible spaced typeface, short plain-language instructions with icons and input examples, generous spacing, one prominent primary action per step, persistent step context and help, no motion or flashing, autofill/password-manager hints, QR and copy options, and clear problem-and-fix error messages.
- Add concise code comments throughout app.ts explicitly mapping the relevant server and client implementation sections to the stated functional, inclusivity, and Security Evaluation requirements.
