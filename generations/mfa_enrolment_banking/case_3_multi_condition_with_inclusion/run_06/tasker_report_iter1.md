## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete HTML/CSS/vanilla-JS mobile SPA, and contains no local modules, build steps, external assets, or remote network calls.
- Implement a responsive, semantic MFA enrolment flow for sign-in, identity verification, authenticator setup, authenticator confirmation, backup-code display, recovery-code verification, success, help, retry, and logout; ensure every internal navigation path works within the SPA.
- Apply dyslexia-inclusive UI rules throughout: legible mobile typography, generous spacing, plain short instructions with icons and input examples, one prominent primary action per step, no animation or reading timer, accessible hints, and specific actionable errors.
- Provide simulated OTP delivery and authenticator provisioning with deterministic values that work; expose test OTPs, provisioning data, and backup codes only to the browser UI and browser console.log, while offering copy controls, QR presentation, manual-secret entry, autofill metadata, reveal/hide, and re-request/retry actions.
- Implement server-side authenticated session handling with an HttpOnly, Secure, SameSite session cookie; rotate the session after authentication, enforce idle and absolute expiry, invalidate it on logout, and require the current session owner for every MFA read or change endpoint.
- Implement server-side CSRF validation for every state-changing MFA request, and reject any client-supplied or manipulated account identifier so MFA data can only be accessed for the session’s authenticated owner.
- Generate OTP secrets, verification challenges, session identifiers, and recovery codes using cryptographically secure randomness; retain OTP secrets and recovery codes only in protected hashed or encrypted server-side form, make submitted verification values single-use and time-bound, and never use browser storage for secrets or tokens.
- Validate all server inputs including email, phone, OTP, recovery code, CSRF token, and redirect destination; encode all dynamic page/API output safely, allow only internal redirect destinations, and use generic non-enumerating authentication failures.
- Add verification-attempt rate limits and temporary lockout behavior with clear retry guidance, without imposing reading deadlines; ensure failed authentication responses do not reveal whether an account exists.
- Set restrictive production security configuration on all responses: HTTPS enforcement and HSTS, CSP with clickjacking protection, X-Content-Type-Options: nosniff, trusted-origin-only CORS, generic error responses without stack traces, and no server logging or URL/error exposure of OTPs, seeds, backup codes, or session tokens.
- Add clear code comments in app.ts mapping each security control and inclusivity feature to the corresponding stated requirement, and verify that simulated actions are logged only in the browser console without revealing secrets in server logs.
