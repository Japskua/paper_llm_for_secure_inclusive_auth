## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete HTML/CSS/vanilla-JS mobile SPA, and contains no external/local module dependencies.
- Add HTTPS-only request handling and security headers on every response: CSP, HSTS, X-Content-Type-Options: nosniff, clickjacking protection, and a trusted-origin-only CORS policy.
- Implement in-memory authenticated-session state with cryptographically random session IDs, HttpOnly/Secure/SameSite cookies, session rotation at sign-in, idle and absolute expiry, and logout invalidation.
- Implement server-side authorization middleware for every MFA route that derives the account exclusively from the session and rejects missing, expired, manipulated, or guessed user identifiers.
- Implement CSRF token generation and validation for every state-changing MFA request, with tokens bound to the authenticated server-side session.
- Provide a responsive, semantic mobile sign-in and identity-verification flow using only inline HTML, CSS, and vanilla browser JavaScript embedded in app.ts.
- Implement a server-validated authenticator enrolment flow that generates a cryptographically secure secret, protects it at rest, provides a provisioning value plus a manual-entry option, and browser-console-logs only the deterministic mock provisioning information returned for testing.
- Implement time-bound, single-use authenticator-code verification with server-side OTP input validation, cryptographically safe comparison, failed-attempt rate limiting, and temporary lockout.
- Implement backup recovery-code generation using a cryptographically secure RNG, protected storage at rest, one-time redemption, and a confirmation screen that browser-console-logs the mock codes for testing without placing them in URLs, cookies, persistent browser storage, server logs, or errors.
- Implement authenticated MFA settings actions to view enrolment status, enable MFA after successful verification, regenerate recovery codes with CSRF protection, and prevent cross-account access.
- Validate all server inputs (including email, phone, OTP, recovery code, CSRF token, and redirect target), allow redirects only to defined internal paths, and contextually escape all rendered dynamic values.
- Ensure all client navigation, forms, verification screens, confirmations, and logout actions resolve to implemented routes or client handlers without external network calls or browser persistent storage.
- Return generic production-safe failures without debug details, use account-enumeration-resistant authentication responses, and add clear code comments in app.ts mapping each security control to the numbered requirements.
