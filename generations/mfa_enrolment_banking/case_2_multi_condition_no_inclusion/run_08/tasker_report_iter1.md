## PARSED_TASKS
- Create a single runnable app.ts Bun HTTPS server that serves the complete mobile SPA from inline HTML, CSS, and vanilla JavaScript, using certs/cert.pem and certs/key.pem with no external assets or network calls.
- Implement authenticated in-memory session handling with opaque HttpOnly, Secure, SameSite cookies; rotate the session on sign-in, enforce idle and absolute expiry on every protected request, and invalidate it on logout.
- Add server-side authorization middleware for every MFA route that derives the account solely from the session and rejects any supplied, manipulated, or guessed user identifier.
- Implement CSRF token issuance and validation for every state-changing endpoint, including MFA enrolment confirmation and backup-code regeneration.
- Implement a mobile-responsive, semantic enrolment flow for sign-in, identity verification, authenticator setup, OTP verification, backup-code display, MFA settings, regeneration, and logout; ensure each internal navigation path is handled by app.ts.
- Generate authenticator secrets, verification challenges, and recovery codes with cryptographically secure randomness; protect stored MFA secrets and recovery codes with strong at-rest encryption or hashing and never persist secrets or tokens in browser storage.
- Implement deterministic mock OTP/authenticator verification that is time-bound and single-use, permits manual secret/code entry when provisioning is shown, and logs test-only delivery/provisioning values only in the browser console.
- Validate all server inputs (including email, phone, OTP, CSRF token, and recovery code), use safe data-access patterns appropriate to the in-memory store, escape all dynamic HTML/DOM output, and restrict redirects to an internal allow-list.
- Rate-limit failed identity and MFA verification attempts, lock the affected session or account after repeated failures, and return generic responses that do not reveal whether an account exists.
- Apply HTTPS-only security configuration: CSP with restrictive script/style/connect sources, HSTS, X-Content-Type-Options: nosniff, clickjacking protection, trusted-origin-only CORS, and generic production error responses without stack traces.
- Add clear source comments mapping the server and client safeguards to the applicable Security Evaluation Requirements, and ensure no logs, URLs, errors, or rendered pages expose session tokens, OTPs, seeds, or stored backup codes except the explicitly required browser-console mock delivery and one-time recovery-code display.
