## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete mobile-responsive HTML/CSS/vanilla-JS SPA, and contains no local imports, build steps, or external network calls.
- Implement secure response handling for every route: HTTPS-only behavior, restrictive trusted-origin CORS, CSP with frame-ancestors, HSTS, X-Content-Type-Options: nosniff, clickjacking protection, and generic production-safe error responses.
- Implement in-memory authenticated-session state with cryptographically random opaque session IDs, HttpOnly; Secure; SameSite cookies, session rotation after authentication, idle and absolute expiry, and logout invalidation.
- Implement server-side MFA endpoint authorization so each request resolves the owner exclusively from the session cookie, rejects missing/expired sessions, and never accepts a client-supplied user identifier to read or modify MFA data.
- Implement CSRF issuance and validation for every state-changing MFA request, binding tokens to the authenticated session and rejecting absent or invalid tokens.
- Implement a mobile-accessible sign-in and identity-verification flow with generic non-enumerating responses, server-side email/phone/OTP validation, internal allow-listed redirects only, and browser console.log mock-delivery of any test verification value.
- Implement cryptographically secure, time-bound, single-use identity verification codes with failed-attempt rate limiting and temporary lockout; do not expose codes in server logs, URLs, errors, or persistent browser storage.
- Implement authenticator enrolment that generates a cryptographically random shared secret, stores it encrypted or strongly protected in server memory, presents a provisioning value with a manual secret-entry alternative, and logs the mock provisioning information only in the browser console.
- Implement server-side TOTP verification for authenticator activation with input validation, time-window enforcement, single-use protection, failed-attempt rate limiting/lockout, and no secret or OTP leakage in responses or server logs.
- Implement cryptographically random backup recovery-code generation, secure at-rest storage using hashes, one-time recovery-code verification, and CSRF-protected regeneration that invalidates the prior set.
- Implement an accessible confirmation and recovery-code display screen that lets the authenticated owner securely view newly generated mock backup codes once, supports manual code submission, and writes test-only mock values to the browser console without using localStorage, sessionStorage, URLs, or non-HttpOnly cookies.
- Add concise code comments in app.ts mapping each server and client security control to the corresponding numbered security requirement, and verify all SPA navigation, forms, error states, logout, and internal links function without dead routes.
