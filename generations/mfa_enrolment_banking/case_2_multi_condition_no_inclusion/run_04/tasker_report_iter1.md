## PARSED_TASKS
- Create a single runnable app.ts Bun server that serves the complete mobile SPA as inline HTML, CSS, and vanilla JavaScript, with no local modules, build steps, frameworks, external assets, or external network calls.
- Configure the Bun server to use certs/cert.pem and certs/key.pem for HTTPS, reject insecure requests, and return generic non-verbose errors without debug output.
- Apply security headers to every response: restrictive CSP, HSTS, X-Content-Type-Options: nosniff, clickjacking protection via frame-ancestors and/or X-Frame-Options, and a trusted-origin-only CORS policy.
- Implement an in-memory authenticated-session model with cryptographically random session IDs, HttpOnly/Secure/SameSite cookies, session rotation after authentication, idle and absolute expiry, and logout invalidation.
- Implement server-side authorization for every MFA route so requests operate only on the authenticated session owner and reject supplied, manipulated, or guessed user identifiers.
- Implement cryptographically random per-session CSRF tokens and require valid CSRF validation on every state-changing MFA request, including enrollment confirmation and recovery-code regeneration.
- Provide a responsive, semantic mobile sign-in and identity-verification flow with accessible labels, clear dyslexia-friendly typography/spacing, and non-enumerating authentication error messages.
- Implement a simulated MFA authenticator-enrollment endpoint that generates a cryptographically random secret, protects the stored secret at rest, and returns a manual provisioning value to the authenticated browser without putting it in URLs, browser storage, cookies, server logs, or error responses.
- Render an MFA enrollment screen that supports manual authenticator-secret entry and OTP submission, and browser-console-log only the deterministic mock provisioning/verification information required for academic testing.
- Implement OTP verification with validated input, a time-bound and single-use deterministic mock code, failed-attempt rate limiting and lockout, and successful MFA activation only after verification.
- Generate recovery codes using a cryptographically secure RNG, store only protected representations at rest, display issued codes only in the authenticated UI and browser console for testing, and never include them in URLs, cookies, server logs, or errors.
- Implement authenticated recovery-code verification and regeneration flows with CSRF protection, one-time code consumption, rate limiting/lockout, and replacement of prior recovery codes after regeneration.
- Validate and normalize all server inputs (including email, phone, OTP, recovery code, and redirect target), escape all dynamic HTML output contextually, and allow redirects only to defined internal paths.
- Implement all SPA navigation and form actions through working routes or client-side handlers, including sign-in, identity verification, authenticator setup, confirmation, recovery-code viewing/regeneration, and logout, with no dead links.
- Add concise code comments in app.ts mapping each security control and UI flow to the relevant numbered requirements, and ensure all simulated actions are logged only with console.log in the browser.
