## PARSED_TASKS
- Create a single runnable app.ts Bun application that serves the complete mobile-responsive SPA with inline semantic HTML, CSS, and vanilla browser JavaScript; do not use local modules, build steps, frameworks, external assets, or network calls.
- Configure the Bun server to use certs/cert.pem and certs/key.pem for HTTPS, redirect/reject insecure traffic as appropriate, and add code comments mapping implementation areas to the stated security requirements.
- Add secure response handling for every route: CSP restricting resources to the same document, HSTS, X-Content-Type-Options: nosniff, anti-clickjacking frame-ancestors/X-Frame-Options, trusted-origin-only CORS, and generic non-verbose errors.
- Implement an in-memory authenticated-session model with cryptographically random session IDs, HttpOnly/Secure/SameSite cookies, session rotation on sign-in, idle and absolute expiration, and logout invalidation.
- Require and verify the current authenticated session on every MFA read or mutation endpoint, deriving the account solely from the session and rejecting supplied, manipulated, or guessed user identifiers.
- Implement CSRF protection for every state-changing endpoint using a server-issued token and strict request validation, while preserving functional same-origin SPA interactions.
- Build the sign-in and identity-verification flow with generic anti-enumeration responses, validated server-side inputs, an allow-listed internal post-login destination, and browser console-only mock delivery of any verification value needed for testing.
- Implement TOTP authenticator enrolment with a cryptographically generated secret protected at rest, a provisioning URI/QR-equivalent display, and a manual-secret path; return the deterministic test verification value to the browser only for console.log.
- Implement server-side OTP verification that accepts the authenticator test code, enforces a time limit and single use, records failed attempts, rate-limits/locks repeated failures, and enables MFA only after successful verification.
- Generate backup recovery codes with a cryptographically secure RNG, store only protected representations at rest, display newly generated codes only in the UI and browser console for testing, and never expose them through URLs, server logs, errors, or browser storage.
- Implement authenticated backup-code verification and regeneration with CSRF enforcement, single-use code invalidation, failed-attempt throttling/lockout, and a clear confirmation UI.
- Validate and normalize all server-side email, phone, OTP, recovery-code, and action inputs; reject malformed values and use safe data-access patterns without constructing executable queries from input.
- Ensure all dynamic server-rendered and client-rendered values use contextual output encoding or safe DOM APIs, never assign untrusted content as HTML, and do not store secrets, OTPs, backup codes, or session tokens in localStorage, sessionStorage, URLs, or non-HttpOnly cookies.
- Create accessible, dyslexia-considerate mobile screens for sign-in, identity verification, authenticator setup, code confirmation, backup-code storage, MFA status, regeneration, and logout, with every internal navigation path handled by the SPA or server routes.
- Add clear source comments identifying how each relevant implementation section satisfies requirements 1 through 5, including authorization, headers, cryptography, input/output safety, and authentication controls.
