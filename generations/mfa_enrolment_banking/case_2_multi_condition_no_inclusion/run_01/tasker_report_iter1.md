## PARSED_TASKS
- Create a single runnable app.ts that starts a Bun HTTPS server using certs/cert.pem and certs/key.pem, serves the complete mobile-responsive SPA from this file, and uses no external assets, packages, build steps, or network calls.
- Implement server-side session authentication with opaque HttpOnly, Secure, SameSite cookies; rotate the session on sign-in, enforce idle and absolute expiry, and invalidate it on logout.
- Add a server-side MFA route/API boundary that authorizes every request from the authenticated session only and never accepts a client-supplied user identifier as authority for viewing or changing MFA data.
- Add per-session CSRF tokens and require valid tokens on every state-changing MFA request, including enrolment confirmation, OTP verification, backup-code use, and backup-code regeneration.
- Configure all responses with restrictive CSP compatible with the inline SPA, HSTS, X-Content-Type-Options: nosniff, clickjacking protection (frame-ancestors and/or X-Frame-Options), and CORS limited to the application’s trusted localhost origin.
- Implement generic production-safe error handling that returns no stack traces, secrets, session identifiers, or account-existence details in responses, URLs, or server logs.
- Implement the mobile sign-in and identity-verification screens with semantic HTML, accessible labels and instructions, responsive phone-width styling, and browser-console-only mock delivery messages.
- Implement authenticated MFA enrolment UI that explains authenticator setup, provides a deterministic mock provisioning secret/code for manual entry, and sends the secret/code to the browser console without placing it in URLs or browser storage.
- Generate MFA secrets and recovery codes with cryptographically secure randomness; retain MFA secrets and recovery codes only in protected server-side form using strong encryption and/or hashing, with recovery codes individually verifiable without plaintext storage.
- Implement time-bound, single-use OTP/recovery-code verification and MFA activation, including deterministic mock values that remain testable while enforcing their stated validity rules.
- Rate-limit failed OTP and recovery-code attempts per authenticated account/session, lock verification after the configured threshold, and return non-enumerating failure messages.
- Implement backup-code display and secure regeneration for the authenticated owner; show newly issued codes once in the UI and browser console, invalidate prior codes on regeneration, and never persist them in browser storage.
- Validate all server inputs with strict allow-lists for email, phone, OTPs, recovery codes, and redirects; allow redirects only to defined internal paths and contextually escape every dynamic value rendered into HTML or DOM.
- Add clear code comments in app.ts mapping each server and client security control to the corresponding numbered security requirement, and verify every SPA navigation/action is handled by an implemented route or client flow.
